README 的首次使用示例与主体在“改进已有包”的路径上相符，也明确了完整复制、发现/刷新和手动读取三种条件。正文关于创建初稿、草稿交付前检查及中途主动介入，也与 SKILL.md 一致；未发现直接规则冲突。

存在一个定位偏窄的可读性问题：开始使用要求“准备改进的完整 Skill 包”，主示例和“它怎样改进已有 Skill”均突出已有包；openai.yaml 的 short_description/default_prompt 也只突出已有技能。首次使用者可能据此认为尚无草稿的创建任务不适用，尽管入口 description、后文创建关系及主体已明确包含它。可在首次使用处加一句“从零创建时先走创建流程，本 Skill 在草稿交付前检查”，并补一个创建场景例子；这属于减少发现后的理解偏差，不是已证明真实宿主漏触发。

另外，“普通业务调用……不启动完整改进流程”容易被孤立理解为绝不介入；主体已经用具体缺口诊断段给出例外，README 也提示业务故障不自动授权全局写回。阅读完整规则后可区分，尚未发现必须扩大全量评测的依据。
