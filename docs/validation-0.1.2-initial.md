本版格式、包内引用与分发检查记录对应当前文件。新增说明与规则片段是文本资源，没有安装脚本。项目规则没有自动写入使用者的项目或全局配置。

skill-creator 格式检查及包内链接检查通过。一个不继承作者聊天的新读者一次检查了 README、接入说明、规则片段、入口及当前验证记录，能正确说明首次安装、首次结果、创建工具关系、定制保留和未验证边界，未发现阻止开始的关键缺项。该阅读调用请求 gpt-6.1-sol / medium；它没有执行安装或业务任务，不能作为运行成功证据。

首次从 GitHub 取回时发现 Windows 的 Git 换行转换改变了文件字节，虽然提交相同，运行文件摘要无法直接复核。已添加 .gitattributes 保留发布字节；该修正不改变技能方法。安装下载、文件一致性与 Agent 自动调用仍是不同检查。

## 真实宿主尝试

在独立临时工作目录的 .agents/skills/skill-improve 中复制完整候选包，使用 Codex CLI 0.160.1 发起新运行。正常用户请求没有点名 Skill Improve，也没有要求预先阅读本 Skill；请求是改进一个含有“按之前约定”的发布摘要技能，并提供已确认的作者业务说明。

请求配置为 gpt-6.1-sol / medium，read-only，ephemeral，忽略用户 config.toml，保留正常技能发现和全局指导。没有传入开发对话或评分答案。模型配置由命令参数设置，未获得服务端模型标识；它不是完全空白系统，也不能证明所有隐藏状态已被清除。

观察到的结果：

1. Agent 主动说会使用 skill-creator 和 skill-improve，并尝试读取项目安装副本的 SKILL.md。
2. 两次 pwsh 只读尝试均被宿主策略拒绝。第二次是该 Agent 自行改为单文件读取，仍失败。
3. Agent 如实返回无法读取与无法可靠改写，没有交付虚假的完成结果。主任务没有改变策略或提高权限继续重试。

因此本次有**发现与选择意图的证据**，没有成功读取正文、执行改进或完成交付的证据。不能将进程退出码 0、说出名称或尝试读取当成完整调用通过。也没有验证项目规则实际被宿主执行、工作中途自动介入、真实宿主的负例或长期可靠性。

运行事件报告 input_tokens 97,325，其中 cached_input_tokens 80,256；output_tokens 504，reasoning_output_tokens 58。按原字段保留，不重复相加。费用、计费口径和可靠等待时间未取得；未据此宣称更省钱。启动时还出现模型列表刷新超时，之后运行仍产生了正常回合事件；该警告也保留为环境限制。

复现输入与事件摘录见 [宿主测试材料](../evals/results/host-discovery.md)。原始本机日志另行保留；公开摘录去除了个人绝对路径，不提供登录态或完整宿主上下文。
