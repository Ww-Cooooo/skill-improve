版本：0.1.1。日期：2026-10-13。状态：主动介入规则已更新，格式和受控阅读检查完成；真实宿主的自动发现与隐式触发尚未验证。

## 本版改动

- 入口 description 覆盖创建、实质修改、效果优化、适配新执行模型，以及任务中途出现的技能工作。
- 明确分工：创建流程主导初稿；本 Skill 提前纳入交接条件，并在可读草稿交付前检查。
- 排除普通业务、纯安装及明确小修引发的整套优化；已有流程继续当前步骤，不自调用，也不与创建工具循环互调。
- 业务中发现缺口可局部诊断，但不据此扩大维护权限或擅改全局副本；主动检查不等于每次都跑完整模型评测。
- agents/openai.yaml 明确允许隐式调用。原版没有关闭默认隐式调用；这次主要补全适用条件与阶段说明，并非安装了自动触发程序。

## 本次检查

1. skill-creator 格式检查、YAML 配置、包内引用与分发完整性检查通过。
2. 一个不继承开发聊天的读者，按八个工作情形检查候选流程：从零创建、任务中途已有草稿、维护失败、业务中发现技能缺口、链接小修、改进进行中、普通业务、纯安装。其判断符合相应介入范围，未将每次介入理解为完整评测。材料及原始阅读结果见 [复现说明](../evals/README.md)。
3. 首次读者发现 README 和界面提示仍偏重已有包；已补清创建入口，并由另一个新读者复核。最终读者正确区分创建工具、本 Skill、普通业务、只读交付及宿主发现前提，未发现核心说明冲突。

两次阅读调用均请求 gpt-6.1-sol / medium，使用不继承父任务历史的设置；调用被接受。读者只获本次规定的技能文件与工作情形，不获作者聊天或预计答案。配置依据是调用参数，未取得服务端模型标识。共享文件系统的读取范围由委托限制，不是操作系统隔离。

这些是**受控的描述和流程理解检查**：读者已被要求阅读候选文件，没有实际执行八项业务，也没有让真实宿主自行选择 Skill。因此不能报告“八次自动触发成功”，也不能证明现有会话已发现新版。两次阅读属于开发检查成本；精确用量、费用和等待时间未取得，不估算。

## 仍需真实宿主验证

安装并确认宿主发现候选包后，分别观察显式调用、不点名的创建/优化请求、工作中途进入技能创建、普通业务与小修，以及已处于改进流程时的继续行为。需要真实读取和执行记录，不能仅以回复中提到 Skill 名称作为通过。

若要求每次交付必经检查，应在使用者选定的创建工作流中配置检查点，并实测该流程。本包不自动修改全局指令、其他创建工具、安装副本或宿主设置来强制触发。其他模型、档位、宿主、长期稳定性与成本改善仍未验证。
