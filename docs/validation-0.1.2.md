2026-10-13 至 2026-10-14，在 Windows 的 Codex CLI 0.160.1 上完成了 **7 个任务回合、6 个会话**的真实自动调用检查。四个适用回合主动读取 Skill Improve、按需读取参考并交付经核对的实际产物；三个不适用回合没有启动完整改进流程。

测试冻结于提交 `dcbacc3c41593431a6d955bca38acf7a1ff06607`。本次只补充验证材料，运行规则和版本号 0.1.2 未变，[运行文件摘要](runtime-files-0.1.2.sha256)保持不变。下表案例通过不代表所有宿主或任务的稳定成功率。

## 实际条件

- 真实调用参数请求 `gpt-6.1-sol`、`medium`，不是模型角色扮演。没有取得服务端模型标识，不进一步推断服务端路由。
- 每个项目在 `.agents/skills/skill-improve/` 安装完整冻结包。普通请求没有点名本 Skill、要求预先读正文、补入评分答案或携带本包开发聊天。正常宿主指导、其他可用技能和工具仍然存在。
- 使用 `--ignore-user-config`，显式设置 `windows.sandbox="elevated"`、`workspace-write`、`approval_policy="never"`，关闭记忆、额外 Agent 和网页搜索功能。Windows 沙箱实现沿用本机既有配置，没有关闭沙箱或修改全局设置。
- 五个一次性会话使用 `--ephemeral`；另一个真实业务会话保留后续接，构成“先做业务、再在同一会话创建 Skill”的两个回合，没有伪造前序聊天。
- 业务输入和安装包经检查保持原字节，两处项目规则与发布片段相同。提示规定只读当前项目和相关技能、只写本项目 output/。读范围不是操作系统级隔离；已检查的执行命令没有用户记忆路径，不能据此宣称所有隐藏状态被清空。
- 每个回合执行一次，运行中没有作者补答案或手工修复产物；结束后才核对成果。最初被阻止的尝试另行保留。

## 配置澄清的含义

记录模型与档位是为了限定结论、避免擅自用别的模型冒充指定测试。已明确且可用的配置应直接沿用，不需要每次重新询问；普通文档改进或错字修正也不因此强制安排模型测试。

本轮实质创建和改进任务已经提供未来配置，执行者没有再要求选择模型，也没有自行追加额外模型评测。**未提供配置时如何询问，本轮未测**；其他对话的一句提问不足以判断是否存在多余确认。

## 障碍、用量与费用边界

最初只读运行被宿主策略阻止读取包，只有选择意图，完整调用未通过，见 [初次记录](validation-0.1.2-initial.md)。后续明确本机既有 Windows 沙箱实现后，独立只读探针能够读取测试文件；正式产物测试使用工作区可写模式。配置和任务写入需求都改变了，因此不把原失败归因为已经单变量验证的某个因素。

本轮 natural-improve 有一次命令以 `rg --files -g AGENTS.md` 无匹配返回 1；此前读取成功，Agent 自行继续交付。其余任务命令未出现非零退出。前四个新会话出现模型列表刷新超时警告，七次运行均出现 PowerShell 会话快照不受支持的警告，仍产生成功的工具和完成事件；这些环境开销保留在记录中。

宿主逐回合累计报告：`input_tokens=840910`，其中 `cached_input_tokens=631680`；`output_tokens=17699`，`reasoning_output_tokens=972` 按原字段另列，不重复相加。七个进程各自耗时总和 1016.32 秒，包含启动和工具等待；部分并行，**不等于用户等待时间或纯推理时间**。各回合时间与原始用量字段见结构化记录。费用、计费口径和实际节省未知，不声称更省钱。
