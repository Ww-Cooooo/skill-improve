# 安装、发现与项目接入

默认先安装完整包，让宿主提供名称和描述，Agent 根据当前工作选择。确实需要把检查接到某个项目的固定创建流程时，再合并可选规则。两者都不需要改写其他 Skill 或 Agent 源码。

## Codex 安装位置

在选定的范围安装一份，避免用户目录和项目目录各留一份不同版本的同名包。

| 使用范围 | 目录 |
| --- | --- |
| 当前项目 | 项目根目录下的 .agents/skills/skill-improve/ |
| 当前用户的各个项目 | 用户主目录下的 .agents/skills/skill-improve/ |

项目安装见 [README](../README.md)。个人安装可在 PowerShell 7、Bash 或 Zsh 运行：

```sh
git clone https://github.com/Ww-Cooooo/skill-improve.git "$HOME/.agents/skills/skill-improve"
```

需要 Git；不使用 Git 时可下载 ZIP，将完整目录复制到相应位置。已有通过安装器放在 .codex/skills 等位置的副本时，先确认宿主实际读取哪份，再决定更新或迁移，不再盲目复制第二份。目录依据是 [Codex 官方技能文档](https://learn.chatgpt.com/docs/build-skills)，具体版本的读取行为仍以本机为准。

安装后在所选项目中新建会话，依次确认：

1. 技能列表或入口信息里包含 skill-improve，路径指向这次安装的副本。
2. 显式请求“使用 $skill-improve 改进……”，能读到正文和本任务需要的包内参考，并交付实际改进。
3. 在另一个新会话中，用正常请求“这个技能换到日常模型后效果变差，请改进并保留原意”，不点名本 Skill。检查实际读取和后续行为。

第二步是可读与显式使用检查，第三步才检查隐式选择；已被前一步提醒过的同一会话不算独立触发测试。说“我会使用”不能代替实际读取与工作证据。正在进行的对话未必加载新版；需要时按宿主方式刷新或重启。

## 可选：接入项目的创建流程

适合经常创建或维护技能、希望少漏掉交付检查的项目。只在使用者选择的项目范围操作：

1. 先确认本 Skill 已安装可读。
2. 阅读 [规则片段](../assets/agents-snippet.md)，将其中的标记块合并到该项目已有的 AGENTS.md；没有文件时才新建。保留原有内容，不另建 AGENTS.override.md 覆盖它。重复接入时更新同一个标记块，不不断追加。
3. 项目内技能可继续按名称从宿主目录发现。若宿主没有技能发现机制，把片段中“从宿主技能目录找到”改为“读取本项目的 .agents/skills/skill-improve/SKILL.md”，且保证该路径实际存在。其他安装位置应替换为真实可读路径。
4. 新建会话核对规则被加载，再实际创建或实质改进一份小技能，观察草稿交付前是否执行相关检查。再做一个只改错字的任务，确认没有启动整套优化。

规则向 Agent 提供早于正文的工作提醒，不能保证所有宿主强制执行，也不会让未安装的文件凭空可读。不要把规则合并进每个产出技能，或悄悄修改 skill-creator、全局 AGENTS.md 和宿主设置。用户明确希望所有项目适用时，可把同一小段合并到其宿主的用户级规则，再按相应范围核对；本包不自动执行这一动作。

业务请求中途出现技能沉淀时，也按当前实际工作判断：已获准创建则交给创建流程产出草稿，再检查交接；仅发现业务问题不能据此擅自新增或改写全局技能。同一轮工作继续已有检查，避免循环调用。

其他宿主若支持技能目录，使用其官方安装与项目规则机制；若只支持读取文件，按 README 的手动方式使用完整包。只复制 agents/openai.yaml 到其他宿主不构成接入。未实测的宿主不宣称兼容。

## 没有触发时，先定位在哪一步

| 现象 | 先检查 | 处理方式 |
| --- | --- | --- |
| 列表没有这个 Skill | 安装层级、发现目录、禁用配置、列表截断或加载警告 | 修正安装或可见性；新会话核对，不靠扩写正文解决 |
| 列表里有，但没有选 | 请求是否确属创建或实质改进、description 是否完整、是否有多个同名版本 | 用独立正常请求复现；必要时采用项目检查点，不堆砌所有关键词 |
| 已选择，却读错或读不到 | 实际读取路径、包内引用、只读权限和副本版本 | 修正引用和安装副本，保持完整包 |
| 已读取，实际成果仍然偏差 | 目标技能方法、任务输入、目标模型、工具与质量标准 | 按诊断流程改进并验证成果；这已不是发现问题 |

发现列表太长时，宿主可能缩短描述或省略条目。把主要用途写在描述前部有帮助，但不能保证被省略的条目仍可被选中；检查实际列表和宿主警告，必要时使用项目路径或显式调用。不要因此擅自卸载使用者的其他技能。

## 更新与撤销

更新前比较当前完整副本与新版本，保留本地定制和可恢复基线。通过 Git 安装且没有本地改动时，可以在该安装目录运行 git pull --ff-only；有改动或分支差异时先合并，不强制覆盖。ZIP 安装先解压到旁边的候选目录，比较后再替换选定副本。更新后区分“源码更新”“安装副本更新”“新会话已读到”，不要合并为一个状态。

取消项目接入时，仅删除 AGENTS.md 中 Skill Improve 的那一个标记块，保留其他规则。卸载时移除选定安装目录；已有会话可能仍保留读过的指令，新会话才适合核对卸载效果。

项目规则的加载范围与覆盖方式见 [AGENTS.md 官方说明](https://learn.chatgpt.com/docs/agent-configuration/agents-md)。本项目实际测试范围见 [验证记录](validation.md)。
